## 二、怎么跑

```powershell
cd "C:\Users\admin\Desktop\软件工程理论基础\选题 2\选题 2"
$env:PYTHONUTF8 = "1"

# 全部 10 个模块
.\.venv\Scripts\python.exe tests\run_module_tests.py

# 只跑某几个模块
.\.venv\Scripts\python.exe tests\run_module_tests.py m03 m07

# 单独跑一个模块（改某块时迭代最快）
.\.venv\Scripts\python.exe tests\test_m03_statemachine.py

# 逐模块体检（子进程隔离，带缺失/失败定位）
.\.venv\Scripts\python.exe tests\check_modules.py
```

或者用启动脚本：

```powershell
.\start_app.ps1 -Modules           # 全部
.\start_app.ps1 -Modules -Only m03,m07
```

在 VS Code 里按 `F5` 也有对应配置，或者直接用终端。

## 四、测试暴露出的真实问题（答辩时如实说明，别被问倒）

### 1. 模块 6：Windows 上语音播报完全静默 ⚠ 建议修

`realtime_pose.py` 第 292–298 行：

```python
def say(text):
    """macOS 自带 say 命令念中文…非 mac 平台静默跳过。"""
    if sys.platform == "darwin" and text:
        subprocess.Popen(["say", text])
```

**Windows 上等于空函数**：动作变形时只有画面文字，没有语音提醒。
这就是模块 6「实时提示**与语音播报**」的一半功能在 Windows 上缺失。

修法（很轻）：在 Windows 分支调用 SAPI（`PowerShell -Command "Add-Type -AssemblyName System.Speech; ..."`）
或 `pyttsx3`。测试里已经把「伪造 darwin 后会起一次 Popen」这条验证通了，改完可直接回归。

### 2. 模块 9：录像 + 错误片段标记**未实现**（项目文档自己承认「已砍」）

- `realtime_pose.py` / `fitness_ui.py` 中 `VideoWriter` / `片段` / `clip` 出现次数 **全为 0**
- 报告里只有错误**次数**（`realtime_pose.py:1123`），没有时间戳
- 唯一录像代码在诊断工具 `camera_check.py:251`（手动按 v 录原始画面，与训练无关）
- 证据：`docs/开发历史.md:217`「模块 9 已砍（价值降级吸收进质量判定的日志）」、
  `CLAUDE.md:222-224` 同

**答辩策略**：主动说「模块 9 我们只做到数据回放，录像与片段标记没做，文档里有记录」，
比被问出来强。或者把它作为「下一步工作」。

### 3. 解释器不校验 `lo < hi` 和 `signal` 名（防御性不足）

- 阈值写反（`lo=160 > hi=140`）且没配 `min_active_duration` 时，
  **人站着不动、信号恒 150°，3 秒内会被数出 5 次**
- `signal` 拼错成 `angel` 仍能加载成功，之后每帧信号为 `None` → **静默永不计数、不报错**

两道防线都在 `validate_config.py` 里，绕过校验器手写配置就会中招。
**这不是 bug，是设计上的单点依赖**，答辩时可以作为「值得改进」讲。

### 4. 两个实现细节不一致（记录，不算缺陷）

- 关键点不可见时，`QualityChecker.check()` 仍会算出实测值且 `ok=False`，
  只靠 `visible=False` 挡住误报；而 peak/valley 无数据时是 `visible=False, ok=True`
- `squat.json` 的 `min_interval=0.4` 因 `min_active_duration(0.25)+enter/exit_hold(0.06+0.06)`
  已强制间隔 ≥0.37s，守门几乎无可触发窗口 —— 测试用 `min_interval=2.0` 单独验证该逻辑
