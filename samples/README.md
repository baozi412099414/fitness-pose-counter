# 示例数据（可直接导进去测试）

这里是可以**直接用的关键点数据**，覆盖三个内置动作的标准与典型错误情形。
不需要摄像头，也不需要自己做动作 —— 数据导进去就能看到计数和判定。

## 怎么用

### 方式 A：界面上导入（推荐）

```bash
cd "/Users/wangwenjing/Desktop/选题 2"
.venv/bin/python fitness_ui.py
```

1. 上半部分「输入」选 **关键点数据**
2. 点「选择视频…」按钮（此时是选数据文件），挑一个 `samples/*.json`
3. 选好**动作**（要和数据的动作对得上，见下表）
4. 点「开始测试」

之后就和用摄像头完全一样：出画面、骨架、HUD 计数、质量提示、语音、写训练历史、出报告。

### 方式 B：命令行快速看结果

```bash
.venv/bin/python pose_player.py --data samples/squat_standard.json
```

秒出结果（不进画面），适合批量核对。

### 方式 C：命令行走完整流程

```bash
.venv/bin/python realtime_pose.py --data samples/squat_standard.json --no-voice
```

## 数据格式

```json
{
  "name": "深蹲 · 标准动作",
  "action": "squat",
  "fps": 30.0,
  "points": [11, 12, 13, ...],
  "frames": [
    [[x, y], [x, y], ...],
    ...
  ]
}
```

| 字段 | 说明 |
|---|---|
| `action` | 用哪个动作来判（`squat` / `pushup` / `jumping_jack`），也可以命令行 `--action` 指定 |
| `fps` | 帧率。**必须给对** —— 防抖参数按秒算，帧率错了时间轴就全偏 |
| `points` | 每帧包含哪些关键点，顺序和 `frames` 里一一对应 |
| `frames` | 每帧一组坐标 `[x, y]` |
| `name` / `note` | 备注，只用于显示 |

**可选** `visibility`（给一个数或每帧一个数）—— **设 0 可以模拟「关键点被遮挡」**。

## 想换成自己的数据

只要照上面的结构改就行。**不用给全部 33 个点** —— 给判定需要的那些就够：

| 动作 | 至少要给的关键点 |
|---|---|
| 深蹲 | 11/12（肩）、23/24（髋）、25/26（膝）、27/28（踝）|
| 俯卧撑 | 11/12（肩）、13/14（肘）、15/16（腕）、23/24（髋）、25/26（膝）、27/28（踝）|
| 开合跳 | 11/12（肩）、13/14（肘）、15/16（腕）、23/24（髋）、27/28（踝）|

**给少了会怎样**：计数信号用到的点必须有，否则完全数不出来；
质量约束用到的点可以不给 —— 缺的点会被判为「无数据」，**既不报错也不扣分**。

## 数据是怎么来的

用 `motion_synth.py`（合成动作轨迹生成器）按人体测量比例程序化生成的，
不依赖任何真人视频：

```bash
# 自己生成一份（参数见 motion_synth.py --help）
.venv/bin/python motion_synth.py --action squat --depth 95 --reps 3 --export my.json
```

> **说明**：这些是**合成数据**，用来验证「判定逻辑是否正确」；
> 它不代表真人在真实摄像头下的精度。详见项目 `CLAUDE.md` 的「阈值现状」一节。
